# Frood — Nutrition Data

Extracted from `TALLER Frood Artworks - editable_Update_V2_260810.pdf` (4 pages, one product
per page). Values are transcribed **exactly as printed on pack** — including the packaging's own
rounding and the `<0.5g` entries. Do not recompute them: on-pack nutrition declarations are a
legal artefact, and the printed figure is the one that must be reproduced.

**Row order below matches the pack** (the standard EU/UK declaration order): Energy → Fat →
Saturates → Mono-unsaturates → Polyunsaturates → Carbohydrate → Sugars → Fibre → Protein → Salt.

All four products are `SERVES 4`, so per-serving = pack weight ÷ 4.

## Paste-ready metafield values

The PDP renders this via `snippets/product-nutrition.liquid`. Nutrition is authored **per blend, on
the `flavour` metaobject** — not per product — and the snippet reaches it through the box product's
existing `custom.included_flavours` list. So a single-flavour box (one entry) gets one table and the
mixed box (four entries) gets four, from one code path.

Two new fields are needed on the **`flavour` metaobject definition**; neither exists yet:

| Field key                | Type                     | Content                        |
| ------------------------ | ------------------------ | ------------------------------ |
| `nutrition`              | `multi_line_text_field`  | One nutrient per line, `Label\|Per serving\|Per 100 g` |
| `nutrition_serving_size` | `single_line_text_field` | e.g. `22.5 g` — shown in the column header |

Per-serving is deliberately the **first** value column. The `<0.5 g` entries are safe to paste
verbatim — the snippet escapes cell values, so the `<` renders as text rather than being parsed as
a tag.

**Why the metaobject and not the products:** the single-pack products are excluded from the Online
Store channel, and Liquid can't reach an off-channel product's data through a metafield reference —
it collapses to blank *silently*. `sections/bundle-builder.liquid` already mirrors `sku` onto the
metaobject for exactly this reason. Reading nutrition through `flavour.product_reference` would risk
an empty nutrition panel with no error to explain it.

**Never merge the blends.** The mixed box shows four separate tables. A single averaged declaration
covering four different foods isn't meaningful and isn't permitted.

## How this was extracted

`pypdf` text extraction alone was **not** reliable here: the artwork's table cells come out of the
content stream in visual-position order rather than reading order, which silently transposed the
mono-unsaturates and polyunsaturates values on three of the four packs. Every table above was
re-read from a high-DPI render of the artwork (the back panel is rotated 180° in the PDF) and
cross-checked arithmetically against the per-100 g column × pack-weight ratio.

If the artwork is re-issued, re-verify visually — don't trust a text dump.
