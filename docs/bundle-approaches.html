Frood · Build Your Box

Bundle fulfilment approaches

There are really two data models, and each has an optional app that closes its one weakness. Model A sells the box as a single product (flat price, clean checkout — but no component stock); an app can bolt on component stock. Model B adds each pouch as its own line (native component stock — but no flat price); an app can bolt on the bundle price. Example throughout: a box of 2× Mexi Fiesta, 1× Smoky Maple, 1× Classic Original. Singles £7.50; box sells flat at £24.00 (a £6 / 20% saving).

Model A

The box is one Shopify product

The box is sold as a single product/line; the chosen flavours ride along as line-item properties. Flat price and a clean one-line checkout come for free.

The gap: Shopify only knows the box SKU, so the single packs are never decremented. Approach 4's app closes exactly this gap — same order shape, plus a background job that adjusts component stock.

Custom app — the added piece

  • Hosted backend (server / serverless) subscribed to orders/paid.
  • Parses _bundle and calls the Inventory API to decrement each component SKU at the right location.
  • Needs hosting + retry / error handling.

Verdict: Keeps the clean one-line checkout and flat price, and gets component stock roughly right — but it's eventually-consistent (oversell risk) and the 3PL still reads _bundle for picking.

Model B

Each pouch is its own line

The 4 pouches are added as individual line items, grouped by a shared _bundle_id. Component stock is tracked natively and in real time, and the 3PL just picks normal lines — no kitting.

The gap: the order totals the sum of the singles — there's no built-in way to apply the flat / discounted box price. Approach 3's app closes exactly this gap — same line items, plus a server-side discount.

    { "title": "Classic Original", "sku": "PACK-ORIG",
      "quantity": 1, "price": "7.50",
      "properties": [ { "name": "_bundle_id", "value": "k3f9a2" } ] }
  ],
  // subtotal = 4 × 7.50 = 30.00 — no discount
  "total_price": "30.00"
}

Each SKU decrements natively & in real time. But the order totals £30, not £24.

Shopify backend

  • Each single pack a real product/variant with SKU + inventory tracking (done).
  • "Build Your Box" product retired as a sellable line (price reference only).

Theme

  • Emit each flavour's variant_id in the flavours JSON blob.
  • Rewrite addToCart() to POST N lines sharing a unique _bundle_id.
  • Group lines into one visual box in the cart; lock per-line qty; group removal.

Custom app

None.

Verdict: Accurate stock and zero app — but no way to discount. Use as-is only if the box price equals 4× a single.

Order — same lines as Approach 2, plus a discount

{
  "line_items": [
    { "title": "Mexi Fiesta Blend", "sku": "PACK-MEX",
      "quantity": 2, "price": "7.50",
      "properties": [ { "name": "_bundle_id", "value": "k3f9a2" } ],
      "discount_allocations": [
        { "amount": "3.00", "discount_application_index": 0 } ] },

    { "title": "Smoky Maple",      "sku": "PACK-MAP",  … },
    { "title": "Classic Original", "sku": "PACK-ORIG", … }
  ],
  "discount_applications": [
    { "type": "automatic",
      "title": "Build Your Box bundle",
      "value_type": "percentage", "value": "20.0" }
  ],
  // 30.00 − 20% = 24.00
  "total_price": "24.00"
}

Delta vs Approach 2: identical line items — the function just adds the discount_applications / discount_allocations that pull £30 down to the flat £24.

Shopify backend

  • Everything from Approach 2, and:
  • + Install the app; it registers an automatic discount backed by the function.
  • + No Shopify Plus needed — discount Functions run on all plans.

Theme

Same as Approach 2 (individual grouped lines).

Custom app — the added piece

  • Shopify app with one product-discount Function extension.
  • Reads each line's _bundle_id, groups them, computes the discount to hit the flat box price.
  • Runs inside checkout (server-side, tamper-proof). Deployed via Shopify CLI.

Verdict: Best fit for "track stock accurately" — the only non-Plus option that prevents overselling and keeps the bundle price. Trade-off: checkout shows 4 lines + a discount. (Watch for clashes with other automatic discounts.)

✕ Cart Transform Function (expand) — Shopify Plus only, ruled out

The theoretical best-of-all-worlds: add one box line that Shopify expands into component lines at checkout — native component stock, flat price, and a single grouped box row at checkout. Cart Transform Functions require Shopify Plus, so it's off the table on the current plan. Listed only so the comparison is complete and the reason is on record.
